# AI_HERMES_STANDARD

Canonical operating standards for the user's Hermes/Jarvis setup.

## Canonical documents

- [`BOT_BOOTSTRAP.md`](BOT_BOOTSTRAP.md) — first file for fresh bots and fresh project sessions. Pulls in the canonical operating contract, Hermes Desktop/session rules, context discipline, Codex routing and goal lifecycle.
- [`JARVIS_OPERATING_CONTRACT.md`](JARVIS_OPERATING_CONTRACT.md) — Hermes-native Jarvis setup, global Codex routing, safety, session hygiene, TouchDesigner and notification policy.
- [`docs/HERMES_DESKTOP_BOTS_SESSIONS_GOALS.md`](docs/HERMES_DESKTOP_BOTS_SESSIONS_GOALS.md) — current Hermes Desktop operating guide: Profile vs Bot vs Bot Chat vs normal Session, `/profile`, `/status`, Standing Goals, `/stop` vs `/goal clear`, fresh project sessions and context-efficient operation.
- [`docs/PROVIDER_EXECUTOR_SETUP_2026-09-06.md`](docs/PROVIDER_EXECUTOR_SETUP_2026-09-06.md) — verified GitHub Copilot CLI setup/authentication and Google Antigravity CLI installation state on Windows.

For project work, keep detailed state in the project repository and give Hermes short pointers to current execution documents rather than pasting large project histories into the orchestrator context.

Changes should normally be promoted through a branch and pull request before landing on `main`.
